# 英超播客翻译 Agent — 实施计划

## 文档定位

本计划以 `REQUIREMENTS.md` 为需求权威，以 `ARCHITECTURE.md` 为模块边界，遵循「最小 MVP → 自动化主链 → 审核与交付 → 长程与沉淀 → 打磨」的既定阶段划分。技术栈与工程设计细节不在本文件展开，见 `TECH_STACK.md`。

本文件仅安排实施顺序、依赖、产出和验收，不实施代码、不安装依赖，也不把尚未验证的外部能力当作已具备能力。阶段按验收结果推进，不预设缺乏实测依据的工期。

### 实施边界

- 发现层负责 feed 管理、增量发现与入队；执行层负责下载、转写、翻译和状态推进。
- 审核层负责人工修改、审批、驳回及评测；交付层只处理已批准版本的看点页、上传与私有交付。
- 沿用 Python 发现与流水线工具、Pi Durable 执行骨架及自研 Runner、静态审核页与 Node 审批服务、boto3 与 Cloudflare R2 的既定归属。
- 输入仅为播客音频，目标语言仅为简体中文，使用 ElevenLabs Scribe v2，不引入视频处理、本地 ASR、公开再分发或多用户能力。
- 需求和架构已定内容不重议；外部能力验证若发现事实不符，记录证据及受影响的验收项，取得确认后再调整，不能静默降低要求。

### 现有资产与复用范围

- 复用 `skills/translate-srt/SKILL.md` 及其 `references/` 中的角色、字幕规范、知识库格式和沉淀规则。
- 复用 `skills/translate-srt/scripts/srt_tools.py` 的输入体检、工作区初始化、整平、译文贴回、检查、重切分与时间轴溯源能力。
- 复用 `skills/translate-srt/scripts/kb_tools.py` 的命中、术语表、错听替换、日志重映射、沉淀与校验能力，并将现有知识库测试纳入回归。
- Scribe 词级时间戳 JSON 重组为一句一条、带说话人前缀的英文 SRT 是项目侧新组件，translate-srt 脚本不覆盖，需自研或复用上游 render 类脚本，并在输入体检前完成。
- 流程状态、override、账本与评测由项目侧持久化管理；英超知识库仍为项目代码之外的纯文本与独立 Git 仓库，不把跨期统计字段塞进知识条目。

## 贯穿各阶段的约束

### 状态与产物先于自动化规模

- 遵循 `discovered → downloaded → transcribed → translated → reviewing → approved → delivered` 主链及 `failed`、`parked` 分支。
- 驳回保留 `reviewing → rejected → translated → reviewing` 的处理记录，重跑范围及原因可查询，不能跳过重新审核直接交付。
- Episode 持久化 guid、feed、标题、发布时间、音频 hash、状态及各阶段产物引用；另落时长与 enclosure（分别对应需求「音频下载与固化」的元数据落库与架构发现层输出），feed 快照是为满足「feed 配置改动不影响在途期数」的实施补充字段，实施时需回填进需求数据模型。feed 后续改名或删除不得影响在途期数。
- 每期独立工作区，原始音频、ASR 原始响应与原始英文 SRT 不覆盖；修正稿、译文稿、复核稿、终稿和审核结果按版本关联。
- 产物清单记录路径、版本、校验信息与生成步骤；状态、checkpoint 和文件不一致时先对账，不凭文件存在就推断步骤成功。
- 人工修改、审批、交付均绑定具体版本；仅有状态名而无法确定批准内容，不满足交付条件。

### 付费调用与外部副作用

- Runner 隔离 experimental API，按 `submit / resume / checkpoint` 的职责封装，不让业务工具直接依赖实验接口细节。
- 落实 intent → 外部调用 → outcome 的记录边界，区分 safe、unsafe 工具；unsafe 调用处于结果未知状态时不得自动重跑。
- Scribe 幂等键按 guid 与音频 hash 构造，但服务端是否支持、有效期和异常语义必须先查证，不能把本地去重当作服务端不重复计费的证明。
- 下载、转写、模型调用、审批和上传分别验证重试语义，不把所有失败都处理成「再执行一次」。
- 账本覆盖转写、翻译、复核、调研及启用的分类等付费调用，记录所属期数、用途、触发时间、模型或服务、用量依据、金额估算、调用标识和结果状态；未知金额不记为零。分类属发现层的独立付费任务，调用记录同样进入项目级账本（schema 与汇总归执行层维护），跨层写入边界在自动化主链落实。

### 自动运行与人工等待

- RSS 轮询路径只处理元数据，不下载音频、不触发模型或付费调用；可选标题/简介分类作为新候选的独立任务处理，费用与结果单独记录，不因重复轮询重复分类。
- 将 skill 原有逐期提问中的已知信息改由持久配置和节目元数据提供：英语输入、简体中文、节目发布日期、主题及调研策略。说话人身份无法可靠确认时采用明确的匿名标签策略，不臆造真名。
- 字幕分条版本选择、最终审核和知识库提交仍由人工决定；需要补充信息的异常进入可恢复等待，不让后台任务无限占用执行进程。
- 发现靠 cron 定时唤醒，执行进程无任务即退出。审核、续签等人工入口的按需启动方式在部署验收中验证，不能用永远常驻的空闲 worker 掩盖生命周期问题。

## 最小 MVP

### 目标

以单一期真实节目验证「固化音频 → 词级转写 → 英文 SRT → 翻译与复核 → 本地待审核产物」，先证明执行骨架和现有 skill 可以接通，再扩展自动发现、完整审核及交付。

### 任务清单

- 建立最小 Episode 持久化、单期工作区、产物清单与账本，人工提供一期节目元数据作为入口；不在此阶段建设完整 feed 调度。
- 建立 Runner 薄封装及单期 Pi Durable conversation，验证每步 checkpoint、transcript 持久化、恢复入口和 safe / unsafe 边界。
- 实现最小下载工具，跟随重定向，保存音频大小、时长与 sha256，后续步骤只读取首次固化版本。
- 接通 Scribe v2 的说话人分离与词级时间戳，保留原始响应；按词边界、句读和说话人变化生成一句一条、带说话人前缀的英文 SRT。
- 验证缺失词时间戳、未知说话人和异常时间区间的处理方式；无法生成可信输入时明确失败或等待处理，不伪造时间点。
- 以最小英超知识库接通 skill：输入体检、工作区初始化、命中与缺口、简报与术语表、转录修正、翻译、复核、重切分、provenance。
- `merge / split` 只在 `stats` 判定需要时运行；正常词级输入不为凑流程而整平。译文由脚本贴回时间轴，LLM 不负责重写时间戳。
- 翻译与调研采用快模型，复核按 skill 与主代理同档；当前阶段验证翻译、复核子代理的文件输入输出与恢复边界，沉淀角色规格按 skill 约定（与主代理同档），本阶段不演练沉淀。
- 保留复核说明、别名替换日志和检查结果；复核修改异常少时安排主代理补查，不能只以子代理「完成」消息判成功。
- 输出复核版与重切分版候选及原始／插值时间点统计，本阶段仅进入本地待审核，不上传 R2、不标记交付。

### 必须完成的验证

- **子代理接入方式**：验证扩展任务、嵌套任务或独立 conversation 中适合本项目的方式，记录模型路由、产物位置、父子完成关联、崩溃恢复、结果去重及成本归属；依据实验结果确定接入方式。
- **fork / steer 的实际用法**：用翻译策略调整和驳回范围变更场景验证是否需要，检查上下文、checkpoint、产物版本和付费调用记录是否混淆。记录采用场景及禁止场景；不适用也要保留验证结论，不强行为主链引入分叉。
- **Scribe 幂等与异常窗口**：查询实施时的官方文档并做受控验证，记录请求键支持、键作用域、有效期、超时后查询或对账手段及计费语义。无法证明结果未知时能安全恢复，付费调用自动重试的验收不得通过。
- **Durable 能力边界**：验证当前可用版本的 checkpoint、safe / unsafe、effect sandwich、memo、parked 行为，区分框架提供能力与 Runner 仍需补齐的能力。
- **费用与耗时基线**：使用实际节目及实际用量记录转写、翻译、复核、调研开销和耗时，不把需求中的典型成本直接当作供应商现价。
- 验证完成后，更新 `ARCHITECTURE.md` 文末待验证事项的结论及证据位置；只回填实验事实，若涉及架构改变则先确认。

### 依赖

- 可用的样本节目、Scribe 与模型凭据、Pi Durable 当前可用版本及其文档。
- 项目内 translate-srt 文件和独立知识库位置；缺库时按 skill 建立最小空库或英超领域底座。
- 先用固定响应或已保存产物完成可重复测试，再以受控真实调用验证外部集成，避免反复转写同一音频。

### 产出

- 单期可恢复的执行骨架及 Runner 接口边界说明。
- 从音频到待审核字幕的完整样本工作区、账本和时间轴溯源报告。
- 子代理接入、fork / steer、Scribe 幂等及 Durable 恢复实验记录。
- 回填验证结论后的架构文档，以及真实单期成本与耗时基线。

### 验收口径

- 同一期音频可产出英文 SRT、修正稿、中文译文、复核稿、重切分候选、术语表和检查记录；产物真实存在且关联正确。
- 英文句子边界可回溯词级时间戳；译文与原文对齐，无未解释漏译、时间轴差异或越界插值。
- 正常完成后重启从 checkpoint 继续，不重复已确认完成的付费步骤；在调用已发出但 outcome 未落盘的窗口中断时，进入可对账状态而不是再次扣费调用。
- 审核前没有上传或交付动作，人工修改的保护要求已纳入后续数据契约。
- 架构待验证事项有可复现实验结果；仍存在的外部阻塞写明影响，不能以 mock 成功替代真实能力验收。

## 自动化主链

### 目标

将已验证的单期执行链连接到多 feed 发现，自动加工至 `reviewing`，做到增量去重、并行隔离、成本可见且空闲不产生付费调用。

### 任务清单

- 实现 feed 增删与配置持久化（字段含名称、feedUrl、所属节目），支持通过 Apple Podcasts Lookup API 检索 feedUrl；保存每期发现时的 feed 快照。
- 接入每 15 分钟 cron，逐 feed 保存 ETag 与 Last-Modified，请求携带条件头；304 不入队、不更新执行链、不触发分类。
- 以 episode guid 建立唯一约束和原子入队，覆盖 cron 重叠、同一期重复返回、首次启动及服务重启；一个 feed 失败不阻塞其他 feed。
- 按既定 Chelsea 过滤策略配置比赛日节目源及可选便宜 LLM 分类。分类只读标题／简介，不先付费转录；结果和依据可查，已分类候选不重复调用。
- 明确发现记录与执行入队边界，使分类剔除的候选也保留去重依据，不因下次轮询再次处理。分类为发现层的独立付费任务，其调用记录写入项目级账本，入队前必须已落账。过滤效果通过人工对照样本检验，不能宣称仅凭元数据能保证找全男足讨论。
- 完善下载失败最多重试 3 次及指数退避、临时文件清理和完成后固化；重复获取同 guid 出现不同 hash 时告警并保留首版，不切换后续输入。
- 将最小 MVP 工具连接到完整状态机，所有转写调用均检查允许状态、固化音频及调用记录；已完成阶段仅复用验证过的产物。
- 实现有界的多期并行及单期执行互斥，防止重叠调度对同一期启动多个写入者；单期失败不阻塞其他期。
- 将 skill 的逐期交互收敛为配置、元数据及异常等待入口，保证普通新期无需人工发起即可进入待审核。
- 完善账本、按期成本汇总与预算标记；启用分类时核算每期分类目标 <$0.005，单期费用超过 $0.5 时留下明确标记，不隐去异常调用。
- 提供按期查询状态、当前步骤、失败原因、产物清单与费用的入口；队列清空后执行进程退出，审核等待不占着模型会话运行。

### 依赖

- 最小 MVP 通过，尤其是子代理恢复边界和付费调用去重已有可用结论。
- 实际 feed、Apple Lookup 响应及 RSS 条件请求测试样本。
- 便宜分类 LLM 的凭据与成本限额配置。
- 可靠的本地状态存储、唯一约束和执行互斥机制。

### 产出

- feed 管理、cron 发现、候选分类及入队链路。
- 支持多期的下载、转写、翻译 worker 和可查询状态记录。
- 分类对照样本、下载异常测试、账本汇总及发现到待审核耗时报告。

### 验收口径

- 重复 RSS、304、cron 重叠和重启均不重复创建 Episode 或重复执行付费步骤；304 和无新节目时没有任何后续模型调用。
- 添加、删除 feed 不破坏在途任务；无效 feed 不影响其他 feed 的正常发现。
- 下载重试、重定向与动态广告 hash 变化可复现，最终加工始终使用首次固化音频。
- 多期并行时，一期失败或等待不阻塞其他期；同一期没有并发写入冲突。
- 普通命中节目自动到达 `reviewing`，不依赖逐期手工运行 skill。
- 从发布时间到待审核的目标为 1 小时内，包含最多一个轮询周期；同时记录实际首次可发现时间和各阶段耗时，feed 延迟与 API 故障单列，不能悄悄缩短统计区间。
- 无新任务时没有付费调用，执行进程退出；单期费用可拆到具体调用，超目标有标记。

## 审核与交付

### 目标

补齐唯一人工审核闸门，保证人工修改永不被重跑覆盖，并将已批准的确定版本交付为中文字幕、看点页和原始音频私有链接。

### 任务清单

- 建设静态审核页与 Node 审批服务，展示音频、同步字幕、原文／译文逐条对照、定点修改和问题标注；审核期由服务直接读取本地产物，不提前上传 R2。
- 支持读取复核版与重切分版，展示 provenance 及插值点统计，让用户选择交付分条版本；记录选择及对应产物版本。
- 建立 override 持久化表与修改历史，关联源句／时间范围、当前产物版本及修改前后文本；不能仅依赖会随拆分重排的 SRT 条目号。
- 在生成待审核稿、局部重跑、重新切分及最终导出时应用人工修改。无法唯一映射的修改保留并标注冲突，禁止静默丢弃、猜测迁移或覆盖。override 写入归审核层，执行层在重跑与生成待审核稿时只读应用；驳回重跑接口携带需应用的 override 版本。
- 实现通过、驳回和重新送审；驳回保存原因及重跑范围，只重跑指定内容及受影响的下游产物，不重新下载或转写无关阶段。
- 审批绑定当前稿、override 修订与交付选择；防重复提交、防旧页面批准新稿。批准后若内容改变，旧批准不能授权新内容交付。
- 在修改保存时同步生成可追溯的评测样本，记录原文、模型版本、修改前后文本、时间范围与问题类别；接口重试不产生重复样本，以源句、时间范围与修改前后文本 hash 作唯一键，重试按该键幂等。
- 实现固定模板看点页，由 Agent 仅填充节目信息、摘要、看点内容和音频跳转时间点；看点内容以已批准版本为依据，不重新混入被驳回稿。
- 实现 boto3 上传 R2，按确定的批准版本生成对象与交付清单；上传字幕、看点页和首次固化音频，完成校验后才推进 `delivered`。
- 对字幕、看点页和音频签发有有效期、限定对象范围的 S3 签名 URL，并支持按需续签；看点页内资源及音频跳转同样保持私有，不以公开桶作为补救措施。
- 将审核与交付入口的单使用者鉴权、路径访问边界、密钥保护、签名 URL 日志脱敏纳入实现；覆盖音频播放、拖动定位和过期链接体验。

### 依赖

- 自动化主链可稳定提供本地 `reviewing` 期数及完整的版本、provenance 和账本信息。
- override 的定位契约、审批版本契约和驳回重跑接口。
- R2 私有桶、最小权限凭据、静态页私有访问方式及实际部署域名环境。

### 产出

- 审核页、审批服务、override 历史、驳回重跑与重新送审闭环。
- 首批交付后按 skill 生成沉淀提案并完成人审闭环；沉淀的集中验收留待长程阶段。
- 自动积累的评测样本及可查询的审批记录。
- 固定模板看点页、上传流程、交付清单和续签入口。

### 验收口径

- 音频播放、字幕同步与跳转可用，修改刷新后仍保留，原文与译文能对应定位。
- 人工修改经过局部重跑和字幕重切分后仍优先；无法映射时阻止错误交付并提示冲突，而不是消失。
- 驳回后按指定范围重跑，未经重新审核不能交付；重复审批请求和旧稿审批不会误推进状态。
- 未批准的期数无法经直接调用上传入口绕过审核，R2 中不存在该期审核前产物。
- 每次实际保存的人工修改都有对应评测样本，重复请求不会凭空增加标注数量。
- 已批准期数得到用户选定版本的中文 SRT、看点页和原始音频三类私有链接；音频 hash 与首次固化记录一致。
- 未签名或过期请求无法访问私有对象，续签不重新翻译、不重新上传内容；看点页内音频同样没有公开访问旁路。
- 上传中断或部分对象失败时不标记 `delivered`，重试完成后清单仍对应同一次批准的版本。

## 长程与沉淀

### 目标

验证跨天、重启及异常恢复，完成领域知识库的人审沉淀闭环和跨期评测，使质量与成本的改善可被实际追踪。

### 任务清单

- 建立故障注入矩阵，覆盖下载中、付费 intent 后、调用已完成但 outcome 未落盘、子代理完成回写前、checkpoint 切换、审核保存、上传和交付状态提交等窗口。
- 对账状态库、Durable transcript、checkpoint、产物及账本；明确自动恢复、人工确认和 parked 的边界，避免因恢复次序错误回退状态或覆盖较新产物。
- 落实连续崩溃计数和熔断，阈值持久化配置；进入 `parked` 后停止自动重试，提供查看证据与人工恢复入口。
- 用 memo 记录审批请求等一次性通知的效果，验证恢复不会反复打扰；不可复用旧内容的批准来解锁新版本。
- 验证多期跨天并行、API 限流与服务重启，审核等待期间停止执行进程，恢复后继续对应期数，不串 conversation 或工作区。
- 建立状态库、产物和独立知识库的备份／恢复流程，确保调用账本与恢复位置一起恢复；恢复后对未知付费结果先对账，不直接重跑。
- 完善英超领域包，覆盖球员、教练、俱乐部、球场、赛事和媒体术语；字段映射沿用 skill 的格式与校验约束，保留标准写法、中文惯用译名、真实 ASR 变体、类型、稳定性和来源。
- 用节目发布日期判断 volatile 月份是否过期，过期的转会、伤病、首发等信息自动进入缺口重查；不能无条件把今日事实套回历史节目。
- 每期交付后生成沉淀提案，纳入术语表、调研、ASR 变体、复核说明及人工 override 中可复用的修正与偏好；沉淀角色只产提案，不直接改库。
- 按 skill 完成临时合并、校验、冲突处理、完整 diff 展示和人工确认后的 Git 提交。不确认则撤销本次变更；并行节目沉淀串行合并，避免互相覆盖或回滚其他期数的改动。
- 每期记录所用知识库版本；未确认的沉淀不成为其他在途任务的默认知识输入。
- 将命中量、缺口数、新专名调研项数、人工修改数和费用保存到项目侧统计中，不依赖知识库自身提供出现次数。
- 实现专名准确率、术语一致率、漏译率和每期人工修改条数趋势；保存指标定义、样本分母及评估范围，按节目时长或条目量辅助对比。
- 审核修改样本与评测结果独立于字幕产物管理，字幕重跑或清理不删除标注；评测注明知识库和模型版本，避免用已纳入知识库的样本伪装独立泛化成绩。

### 依赖

- 审核、驳回、交付链路及付费调用恢复保护已可运行。
- 多期真实样本和人工审核修改、知识库独立 Git 仓库。
- checkpoint、产物版本、调用记录及 override 有可关联的持久标识。

### 产出

- 故障注入结果、恢复／熔断／人工处理手册和备份恢复演练记录。
- 英超领域底座、逐期沉淀提案与人工确认提交记录。
- 独立评测集、指标定义和跨期质量／调研／成本趋势报告。

### 验收口径

- 跨天等待审核、进程重启及受控崩溃后，已完成产物不丢失、合法状态不回退、人工修改不被覆盖，已确认完成的付费调用不重复执行。
- 结果未知的 unsafe 调用不会自动重放；无法查证时进入人工处理，不能以「大概率没扣费」作为恢复依据。
- 连续崩溃达到配置阈值即 parked，重启不会清空计数并继续撞失败；人工恢复留有原因记录。
- 多期故障隔离成立，memo 不导致重复审批通知，也不导致跳过对新版本的审核。
- 备份能恢复代表性期数、账本、override 与知识库；恢复后未知调用仍受保护，不重复计费。
- 新译名、真实错听变体和可复用偏好经人工确认后提交，下一期能命中；未确认内容、冲突项和一次性润色不会被当成已知事实传播。
- volatile 条目能按节目日期进入重查，知识库校验通过，不留下未确认的脏改动。
- 每次人工修改可追溯到评测样本，所有指标有明确分母；只有改动样本时不把「未改」等同于「已确认正确」，不足以计算的指标明确标注待补充验证范围。
- 连续多期能展示知识命中、调研项数和人工修改趋势；是否递减由数据判断，不虚构必须单调下降的结果。

## 打磨

### 目标

用真实节目和运行演练完成性能、成本、隐私与运维验收，形成可在 VPS 长程使用的版本。

### 任务清单

- 在目标 VPS 部署完整链路，明确 cron、按需执行、审核入口和续签入口的启动与退出方式，完成配置、凭据、目录权限及环境检查文档。
- 验证无任务和纯审核等待时无后台模型调用、无空闲执行 worker；按需服务能在用户访问时正常启动，服务停止后待办和审批数据不丢失。
- 用典型短节目、长节目、多说话人节目、密集专名节目及转会窗／德比样本做端到端回归，保留重复 RSS、下载变化、限流、重启和驳回场景。
- 基于实测优化并行度、模型路由、缓存和知识库复用，保持复核模型规格与人工闸门不降级；优化前后对比质量、成本及耗时。
- 校验发布到待审核的小时级目标，单独展示轮询等待、feed 延迟、下载、ASR、调研、翻译和复核耗时，不把人工审核等待算成机器加工瓶颈。
- 核算单期 <$0.5 目标及典型 $0.30 参考（对照需求拆分：转写 $0.18 + 翻译 $0.12，以账本逐项核对），观察转会窗／德比期上浮是否落在需求预期上限（$0.55）；超过目标线时账本标记并记录优化方向，不强行把不完整费用算进目标线内。
- 完善运行摘要与异常提示，覆盖 feed 持续失败、下载 hash 变化、费用超标、结果未知的付费调用、parked、审核待办和交付失败；避免重复告警。
- 检查审核服务访问控制、R2 权限、签名链接过期与续签、看点文本转义和密钥／私有链接脱敏，防止通过路径、静态页或日志绕过私有访问。
- 检查磁盘占用与产物保留策略，清理前保护首次固化音频、当前交付版本、override、调用记录与评测样本，不破坏可恢复性。
- 完善操作手册：添加节目源、查看任意期数、处理失败或 parked、审核及驳回、续签、确认沉淀、备份恢复和升级回滚；实验接口升级先通过 Runner 回归。
- 汇总需求覆盖证据和已知限制；外部能力仍未满足的事项不得被包装成已完成。

### 依赖

- 前述阶段通过，具备真实账本、跨期样本和故障恢复证据。
- 目标 VPS、私有访问入口、R2 与备份目的地可用于最终演练。

### 产出

- VPS 部署与运维手册、完整回归结果、隐私检查结果。
- 真实节目的质量／耗时／费用报告及调优记录。
- 需求验收清单、证据索引和已知限制说明。

### 验收口径

- 从 cron 发现到审核、驳回、重新审批、私有交付、续签和知识库沉淀的完整路径可由使用者实际操作。
- 新节目在正常外部服务条件下达到发布后 1 小时内生成待审核初稿的目标，异常情况有可解释的分段耗时和失败记录。
- 每期费用能追溯到各次付费调用，目标内与超目标样本均如实展示；无新节目期间零付费调用。
- 未批准产物不可交付，交付物及嵌入资源保持私有，过期链接不能继续读取对象，续签可用。
- 代表性崩溃、限流、并行、重启、审核修改和备份恢复场景通过，没有重复计费、产物丢失、越权访问或 override 覆盖问题。
- 全部功能需求都有对应验收证据；存在硬性阻塞时明确不通过，不以文档齐全代替运行结果。

## 需求覆盖检查

### 节目源与增量发现

- feed 增删、Apple Lookup、配置不影响在途期数：自动化主链。
- Chelsea 过滤及便宜分类：自动化主链；分类成本在打磨时复核。
- 轮询、条件请求、304、guid 去重和纯元数据约束：自动化主链；重叠与重启在长程阶段加压。

### 音频、转写与翻译

- 下载重定向、hash 与大小、首版固化、重试与元数据：最小 MVP 建立，自动化主链补全异常分支。
- Scribe v2、说话人分离、词时间戳、一句一条英文 SRT：最小 MVP。
- 幂等键、许可状态及不重复付费：最小 MVP 验证外部能力，自动化主链接入状态约束，长程阶段故障注入。
- skill 全流程、快／强模型路由、按需整平、时间轴溯源：最小 MVP ；自动化主链消除逐期手工触发。

### 知识库与评测

- 英超实体、术语、错听变体、纯文本独立 Git：最小 MVP 接通最小底座，长程与沉淀完善。
- volatile 重查、新知识与偏好的人审沉淀：审核与交付启动首批，长程与沉淀延续并集中验收。
- 人工修改自动标注：审核与交付；独立评测集、指标和跨期趋势：长程与沉淀。

### 审核、看点页与交付

- 音频同步、双语对照、修改、问题标注、审批和驳回范围重跑：审核与交付。
- override 持久化、重跑优先与版本安全：审核与交付；长程阶段验证恢复。
- 用户选择交付分条版本、固定模板看点页、音频跳转及私有静态托管：审核与交付。
- R2、S3 签名 URL、范围与有效期、续签、三类交付物：审核与交付；打磨验证部署与隐私。

### 长程调度、成本与整体目标

- 按需唤醒、空闲无执行进程、多期并行和失败隔离：自动化主链建立，长程与沉淀及打磨验证。
- - 跨天生命周期、checkpoint、产物清单：最小 MVP 建立接口，长程与沉淀完成验证。
- 查询状态与产物：自动化主链提供查询入口，长程与沉淀验证跨天恢复。
- 连续崩溃熔断：最小 MVP 验证 parked 能力边界，长程与沉淀落实并验证。
- 调用金额、触发时间、期数归属、预算超标及空闲零付费：最小 MVP 建立账本，自动化主链完善，打磨最终核算。
- 小时级初稿、私有交付、人审唯一闸门、知识复用与调研减少：分别在主链、审核与交付、长程与沉淀建立证据，打磨统一验收。

## 阶段推进与交接

- 最小 MVP 完成前，不扩展全量 feed、不批量触发付费转写。外部幂等或恢复语义不成立时，相关自动重试保持关闭并记录阻塞。
- 自动化主链完成前，不把「手工运行成功」视为无人值守已完成；审核与交付完成前，所有真实产物停留在本地待审核区。
- 长程验证贯穿实施，沉淀的人审闭环随首批交付启动；跨天恢复、故障矩阵与评测的集中验收在完整审核交付链路可用后进行。
- 每阶段交接保留：实现变更摘要、通过与未通过的验收项、复现入口、样本与产物位置、调用费用、恢复说明和剩余阻塞。
- 本计划不直接触发任何安装、部署、外部付费调用、知识库写入或 R2 上传；这些动作由后续实施任务按对应阶段开展。
