# 英超播客翻译 Agent — 需求文档

- 版本：0.2（草稿）
- 日期：2026-11-04
- 状态：讨论中

## 项目概述

本项目是一个部署在 VPS 上的长程自动化系统：定时发现 Sky Sports 英超相关播客的新节目，下载音频，经语音转写与 LLM 翻译流水线产出中文字幕，人工审核通过后交付字幕文件与在线看点页。系统跨期维护英超领域知识库（译名、术语、转写错听变体），持续降低后续期数的人工校对量。

系统分层：

| 分层  | 本质                                     |
| --- | -------------------------------------- |
| 发现层 | cron 轮询 + ETag/304 条件请求 + guid 去重      |
| 执行层 | Agent 核心：模型决策 + 工具调用循环 + 每步 checkpoint |
| 审核层 | 人工审核页 + override 表                     |
| 交付层 | 静态托管 + S3 预签名 URL 私有交付                 |

## 背景与现状

- Sky Sports 播客通过 RSS 公开分发（已知多数节目托管于 feeds.captivate.fm），音频为 mp3 直链，无鉴权、无 DRM，但 **feed 不提供转写稿**
- 现有 `translate-srt` skill 提供从 SRT 到中文字幕的完整流水线（输入体检、知识库复用、术语表、翻译、复核、重切分、沉淀），但流程由人工逐期触发，且输入 SRT 需人工准备
- 现状的人工成本集中在：发现新节目、下载、转写、组织逐期翻译
- 本项目的目标：把「最终审核」之前的所有环节自动化，人工只做校对与审批

## 目标与非目标

### 目标

- 快速产出初稿：新节目发布后 1 小时内（15 分钟轮询粒度）自动产出待审核的中文字幕初稿
- 交付物：每期交付中文字幕 SRT、一期看点展示页、私有访问链接
- 知识库沉淀：跨期积累英超领域知识库，新专名调研项数随期数递减
- 断点恢复：进程重启、崩溃、API 限流后可从断点恢复，不重复产生付费调用
- 并行处理：多 feed、多期节目并行处理，单期失败不阻塞其他期
- 人工审核闸门：人工审核是交付前的唯一必经闸门

### 非目标（明确不做）

- 不处理视频：输入仅为播客音频 mp3；不做视频切片、不做视频播放器
- 不做公开再分发：音频与字幕仅以私有签名链接交付个人使用
- 不自研 ASR：使用 ElevenLabs Scribe；不引入本地 Whisper 等替代方案
- 不自动发布：任何产物未经人工审批不得进入交付区
- 不做多用户：单一使用者
- 不做多语言：目标语言仅简体中文

## 使用场景

使用者即所有者本人。

- 场景·常规：周末比赛结束后数小时内播客发布。系统自动完成下载、转写、翻译；使用者在审核页校对，通过后获得字幕与看点页
- 场景·周中：无新节目时系统空闲，不产生付费调用；周中轮次、欧战、发布会节目出现时按相同流程处理
- 场景·聚焦球队：针对某支球队的多档节目聚合处理，同一赛季共享知识库，跨期保持译名与术语一致

## 功能需求

### 节目源管理

- 支持添加/删除多个 RSS feed；feed 信息含：名称、feedUrl、所属节目
- 支持通过 Apple Podcasts Lookup API 检索节目 feedUrl（已知可用：feeds.captivate.fm 下各 Sky Sports 节目）
- feed 配置改动不影响正在处理的期数
- 过滤策略（已定）：「只关心 Chelsea」推荐订比赛日节目（PL Podcast + Essential Football + Gary Neville）+ 转录前用便宜 LLM 对标题/简介分类（每期 <$0.005）；纯元数据过滤会漏男足讨论（实测本周男足命中 0 期）

### 增量发现

- 每 15 分钟轮询全部 feed，请求携带 ETag/If-Modified-Since；304 时不产生任何后续处理
- 以 episode guid 为去重主键；同一 guid 不重复入队
- 轮询为纯元数据操作：不下载音频、不调用付费 API、不调用 LLM

### 音频下载与固化

- 从 enclosure 直链下载 mp3，自动跟随 302 重定向
- 下载完成后记录 sha256 与文件大小；同一 guid 重复下载 hash 不一致时（动态广告插入所致），以首次固化版本为准并记录告警
- 下载失败重试 3 次，指数退避；仍失败则标记 failed，不阻塞其他节目
- 节目元数据（标题、发布时间、时长）与音频一并落库

### 语音转写

- 使用 ElevenLabs Scribe v2，开启说话人分离
- 转写结果必须保留词级时间戳，用于重组为「一句一条」的 SRT
- 转写输出：原语言（英语）SRT，一句一条，含说话人前缀
- 幂等：转写调用携带幂等键（由 episode guid + 音频 hash 构造）；重试不产生二次计费
- 转写为付费调用，仅允许在任务状态机许可的时机执行

### 翻译流水线（复用 translate-srt skill）

- 以转写产出的 SRT 为输入，按 translate-srt 既有流程执行：输入体检、工作区初始化、知识库加载、术语表生成、翻译、复核、重切分
- 目标语言：简体中文
- 输入源自词级时间戳重组，translate-srt 的 merge/split 整平预期大部分为 no-op；仅当 `stats` 判定需要时执行
- 翻译与复核由子代理执行，模型规格按 skill 约定（翻译可用快模型，复核与主代理同档）
- 每条字幕的时间轴可溯源：`provenance` 区分原始转写时间点与插值时间点

### 领域知识库

- 使用 translate-srt 的知识库机制，建立英超领域包：球员、教练、俱乐部、球场、赛事、媒体术语
- 每条实体含：原文写法、中文译名（遵循中文媒体惯例）、ASR 错听变体、类型、稳定性标记
- 易变信息（转会状态、首发、伤病）标记 volatile 及月份，过期后自动列入重查
- 每期完成后执行沉淀：新专名、新错听变体、复核偏好写入知识库，人工确认后提交
- 知识库为纯文本 + git 管理，独立于本项目代码

### 人工审核

- 每期翻译完成后进入「待审核」状态；审核通过前系统不得进入交付环节
- 审核页提供：音频播放与字幕同步显示、原文/译文逐条对照、定点修改、问题标注
- 审核结果：通过 → 进入交付；驳回 → 记录原因并按指定范围重跑（如仅重新翻译指定条目）
- 人工修改必须持久化保留，任何重跑中人工修改优先于模型产物，不可被覆盖

### 评测（自研模块，标注从审核修改自动生长）

- 审核时每次人工改动即一条标注样本，自动写入评测集，零额外标注成本
- 指标：专名准确率、术语一致率、漏译率、每期人工修改条数趋势
- 评测集独立存储，用于跨期追踪质量趋势与新专名调研项数递减验证

### 看点页

- 每期审核通过后，基于固定模板生成看点页：节目信息、看点摘要、看点内容、对应时间点（可跳转音频）
- 模板固定，Agent 仅填充内容字段
- 看点页部署至可私有访问的静态托管

### 交付

- 每期交付物：中文字幕 SRT（按用户选定的分条版本）、看点页链接、原始音频私有链接
- 存储使用 Cloudflare R2，以 S3 兼容 API 签名 URL 交付；不使用 WebDAV
- 交付链接有有效期与访问范围限制

### 调度与长程运行

- 「常驻监听、按需唤醒」：发现层常开且近零成本，执行层仅在存在待处理节目时运行；空闲时段不运行任何常驻进程
- 单期生命周期（发现 → 交付）可跨数天，含人工审核等待；期间进程重启、崩溃不得导致：重复付费调用、产物丢失、状态回退
- 多期并行处理；单期失败不阻塞其他期
- 每步执行前后有可查询的状态与产物清单，可随时确认任意一期所处阶段
- 连续崩溃的任务熔断：停止自动重试，转人工处理

### 成本与计费透明

- 记录每次付费调用（转写、翻译）的金额估算、触发时间、所属期数
- 单期成本目标 <$0.5（典型 $0.30：转写 $0.18 + 混合模型翻译 $0.12）；转会窗/德比周可能上浮至 $0.55，超目标线时在账本标记并视情优化
- 空闲时段（无新节目）零付费调用

## 数据模型

**Episode（一期节目）**：guid、feed、标题、发布时间、音频 hash、状态、各阶段产物路径

**状态机（含驳回边）**：

```
discovered → downloaded → transcribed → translated → reviewing → approved → delivered
                ↓ 任意阶段可转入 failed / parked
reviewing → rejected（记录原因与重跑范围）→ translated（按范围重跑，override 存活）
```

**知识库**：领域包（entities / glossary / style / sources）+ 全局 aliases.tsv + git

**每期产物清单**：原始 SRT、修正稿、译文稿、复核稿、终稿、看点页、审核记录、成本记录、评测样本
