# 播客翻译 Agent — 需求文档

- 版本：0.3（草稿）
- 日期：2026-11
- 状态：讨论中

## 项目概述

本项目是一个部署在 VPS 上的长程自动化系统：定时发现 Sky Sports 英超相关播客的新节目，下载音频，经语音转写与 LLM 翻译流水线产出中文字幕，经审核箱的人工干预或超时自动审批后发布到私人播客库，提供音频、同步字幕、看点与 SRT 下载。系统跨期维护英超领域知识库（译名、术语、转写错听变体），持续降低后续期数的人工校对量。

系统分层：

| 分层  | 本质                                     |
| --- | -------------------------------------- |
| 发现层 | cron 轮询 + ETag/304 条件请求 + guid 去重      |
| 执行层 | Agent 核心：模型决策 + 工具调用循环 + 每步 checkpoint |
| 审核层 | 待审核收件箱 + 人工干预 / 超时自动审批 + override 表 |
| 交付层 | 私人播客库 + 静态看点页 + R2 私有对象与签名 URL       |

## 背景与现状

- Sky Sports 播客通过 RSS 公开分发（已知多数节目托管于 feeds.captivate.fm），音频为 mp3 直链，无鉴权、无 DRM，但 **feed 不提供转写稿**
- 现有 `translate-srt` skill 提供从 SRT 到中文字幕的完整流水线（输入体检、知识库复用、术语表、翻译、复核、重切分、沉淀），但流程由人工逐期触发，且输入 SRT 需人工准备
- 现状的人工成本集中在：发现新节目、下载、转写、组织逐期翻译
- 本项目的目标：把「最终审核」之前的所有环节自动化，人工只做校对与审批

## 目标与非目标

### 目标

- 快速产出初稿：新节目发布后 1 小时内（15 分钟轮询粒度）自动产出待审核的中文字幕初稿
- 交付物：每期交付中文字幕 SRT、一期看点展示页、私有访问链接
- 知识库沉淀：跨期积累英超领域知识库，新专名调研项数随期数递减
- 断点恢复：进程重启、崩溃、API 限流后可从断点恢复，不重复产生付费调用
- 并行处理：多 feed、多期节目并行处理，单期失败不阻塞其他期
- 审核与发布窗口：每期翻译后先进入 12 小时待审核窗口，人工可提前通过或驳回；到期未处理则自动审批并发布到私人播客库

### 非目标（明确不做）

- 不处理视频：输入仅为播客音频 mp3；不做视频切片、不做视频播放器
- 不做公开再分发：音频与字幕仅通过单用户私人播客库及其私有签名资源交付个人使用
- 不自研 ASR：使用 ElevenLabs Scribe；不引入本地 Whisper 等替代方案
- 不绕过审核窗口：新稿不得生成后立即发布；仅允许人工提前通过或待审核窗口到期后自动发布到单用户私人播客库
- 不做多用户：单一使用者
- 不做多语言：目标语言仅简体中文

## 使用场景

使用者即所有者本人。

- 场景·常规：周末比赛结束后数小时内播客发布。系统自动完成下载、转写、翻译；使用者在审核页校对，通过后获得字幕与看点页
- 场景·周中：无新节目时系统空闲，不产生付费调用；周中轮次、欧战、发布会节目出现时按相同流程处理
- 场景·聚焦球队：针对某支球队的多档节目聚合处理，同一赛季共享知识库，跨期保持译名与术语一致
- 场景·异步审核：多期节目可先积攒在审核箱；用户有空时抽检、定点修改或直接通过，未处理的节目在窗口到期后自动进入私人播客库
- 场景·发布后修订：收听已发布节目时仍可再次编辑；修订期间旧版继续可听，新版重新通过后替换

## 功能需求

### 节目源管理

- 支持添加/删除多个 RSS feed；feed 信息含：名称、feedUrl、所属节目
- 支持通过 Apple Podcasts Lookup API 检索节目 feedUrl（已知可用：feeds.captivate.fm 下各 Sky Sports 节目）
- feed 配置改动不影响正在处理的期数
- 过滤策略（已定）：「只关心 Chelsea」推荐订比赛日节目（PL Podcast + Essential Football + Gary Neville）+ 转录前用便宜 LLM 对标题/简介分类（每期 <$0.005）；纯元数据过滤会漏男足讨论（实测本周男足命中 0 期）

### 增量发现

- 每 15 分钟轮询全部 feed，请求携带 ETag/If-Modified-Since；304 时不产生任何后续处理
- 以 episode guid + feed 为去重主键；同一 feed 的同一 guid 不重复入队，未入队候选也保留去重记录
- 新 feed 首次轮询默认只建立历史基线，不自动入队存量节目；只有显式选择处理存量，或首轮之后新增的节目才进入执行层
- 轮询为纯元数据操作：不下载音频、不调用付费 API、不调用 LLM（启用的独立分类任务除外）

### 音频下载与固化

- 从 enclosure 直链下载 mp3，自动跟随 302 重定向
- 下载完成后记录 sha256 与文件大小；同一 guid 重复下载 hash 不一致时（动态广告插入所致），以首次固化版本为准并记录告警
- 下载失败重试 3 次，指数退避；仍失败则标记 failed，不阻塞其他节目
- 节目元数据（标题、发布时间、时长）与音频一并落库

### 语音转写

- 使用 ElevenLabs Scribe v2，开启说话人分离
- 转写结果必须保留词级时间戳，用于重组为「一句一条」的 SRT
- 转写输出：原语言（英语）SRT，一句一条，含说话人前缀
- 幂等：转写调用携带幂等键（由 episode guid + 音频 hash 构造）；重试不产生二次计费
- 转写为付费调用，仅允许在任务状态机许可的时机执行

### 翻译流水线（复用 translate-srt skill）

- 以转写产出的 SRT 为输入，按 translate-srt 既有流程执行：输入体检、工作区初始化、知识库加载、术语表生成、翻译、复核、重切分
- 目标语言：简体中文
- 输入源自词级时间戳重组，translate-srt 的 merge/split 整平预期大部分为 no-op；仅当 `stats` 判定需要时执行
- 翻译与复核由子代理执行，模型规格按 skill 约定（翻译可用快模型，复核与主代理同档）
- 每条字幕的时间轴可溯源：`provenance` 区分原始转写时间点与插值时间点

### 领域知识库

- 使用 translate-srt 的知识库机制，建立英超领域包：球员、教练、俱乐部、球场、赛事、媒体术语
- 每条实体含：原文写法、中文译名（遵循中文媒体惯例）、ASR 错听变体、类型、稳定性标记
- 易变信息（转会状态、首发、伤病）标记 volatile 及月份，过期后自动列入重查
- 每期完成后执行沉淀：新专名、新错听变体、复核偏好写入知识库，人工确认后提交
- 知识库为纯文本 + git 管理，独立于本项目代码

### 人工审核与审核箱

- 每期翻译完成后进入审核箱；多期待审核节目可长期积攒，等待期间不占执行 worker，也不要求用户立即处理
- 审核页提供：音频播放与字幕同步显示、原文/译文逐条对照、定点修改、分条版本选择、通过、按范围驳回与「保留待审」
- 审核语义是「确认内容可以交付」，不要求逐条校对；用户可抽检后直接通过，未修改不代表已证明全部译文正确
- 每个新待审版本默认开启 12 小时人工干预窗口；人工通过可立即进入交付，到期未处理由系统以 `auto_timeout` 方式自动审批
- 打开页面和播放音频不重置计时；保存产生新版本的修改后重新计时，驳回取消旧计时，重跑生成新待审稿后重新计时；「保留待审」暂停自动审批
- 自动审批由定时任务执行，事务内复核状态、产物版本与 hash；override 映射冲突、产物缺失或校验失败时禁止自动审批
- 审批记录区别人工通过与超时自动通过，并绑定最终产物版本与 SHA256；内容变化后旧审批失效
- 人工修改持久化到 SQLite override 表，以源稿版本、时间范围和原文 hash 定位，SRT 条目号仅用于展示
- 驳回按时间范围局部重跑；模型生成新候选稿后重新应用有效 override，同位置人工内容优先；无法唯一映射时保留修改、标记冲突并阻止发布
- 已批准未发布或已发布节目均可再次编辑；已发布节目修订期间旧版继续在线，新版重新通过并完成交付后再原子替换

### 评测（后续阶段，不在审核与私人播客库 MVP）

- 当前阶段不建设评测表、问题标签、评分任务或统计报表；override 仍保留原文、修改前后文本、时间与产物版本，供后续补建历史样本
- 后续启用时，审核及发布后修订的每次人工改动生成一条标注样本；独立保存，不因字幕重跑或清理删除
- 后续指标包括修改密度、直接交付率、驳回率、发布后修订率、专名与术语问题趋势；抽检时不得把未修改条目当作已确认正确

### 看点页

- 每期审批通过后，基于固定模板生成看点内容：节目信息、看点摘要、看点内容、对应时间点（可跳转音频）
- 模板固定，Agent 仅填充内容字段
- 看点整合进私人播客库的单期页面，也可部署为私有静态页

### 交付与私人播客库

- 审批通过并交付完成的节目自动进入私人播客库；首页可查看全部节目，并按节目源与发布时间浏览
- 单期页面提供音频在线播放、字幕同步与点击跳转、原文／译文对照、看点、SRT 下载和「再次编辑」
- 每期最终交付物：用户选定分条版本的中文字幕 SRT、看点页、原始音频；中间产物默认不展示
- 存储使用 Cloudflare R2 私有桶，以 S3 兼容 API 上传；不使用 WebDAV
- 用户使用稳定的私有节目地址，服务端按需签发短期、限定对象范围的音频与文件 URL；签名过期不影响节目地址，可重新签发
- 新修订只有在重新审批、上传与校验完成后才切换当前发布版本；上传失败时旧版继续可用

### 调度与长程运行

- 「常驻监听、按需唤醒」：发现层常开且近零成本，执行层仅在存在待处理节目时运行；空闲时段不运行任何常驻进程
- 单期生命周期（发现 → 交付）可跨数天，含人工审核等待；期间进程重启、崩溃不得导致：重复付费调用、产物丢失、状态回退
- 多期并行处理；单期失败不阻塞其他期
- 每步执行前后有可查询的状态与产物清单，可随时确认任意一期所处阶段
- 连续崩溃的任务熔断：停止自动重试，转人工处理
- 超时自动审批与已批准版本的交付由 cron 或按需任务扫描执行；等待 12 小时窗口期间不运行常驻执行 worker，也不产生模型调用

### 成本与计费透明

- 记录每次付费调用（转写、翻译）的金额估算、触发时间、所属期数
- 单期成本目标 <$0.5（典型 $0.30：转写 $0.18 + 混合模型翻译 $0.12）；转会窗/德比周可能上浮至 $0.55，超目标线时在账本标记并视情优化
- 空闲时段（无新节目）零付费调用
- 提供只读「用量与费用」管理页：按节目、用途、供应商、模型和状态查看用量、成本估算与异常；区分账本估算、模型返回成本和未对账金额，R2 费用不混入项目账本

## 数据模型

**Episode（一期节目）**：guid、feed、标题、发布时间、音频 hash、状态、各阶段产物路径、当前待审版本、auto_approve_at、自动审批暂停标记

**状态机（含人工干预、超时审批、驳回与发布后修订）**：

```
discovered → downloaded → transcribed → translated → reviewing → approved → delivered
                ↓ 任意阶段可转入 failed / parked
reviewing → approved（人工提前通过或 12 小时到期 auto_timeout）
reviewing → rejected（记录原因与时间范围）→ translated（局部重跑，override 存活）→ reviewing
approved / delivered → reviewing（再次编辑生成新修订）
```

已发布节目进入新修订时，发布记录仍指向旧版；节目库是否展示依据有效发布记录，而不是仅看 Episode 当前状态。审批记录保存方式、产物版本与 SHA256；发布记录保存当前上线版本。

**override**：源稿版本、开始／结束时间、原文 hash、被修改产物版本、修改前后文本、请求幂等键与创建时间；修改历史追加保留。

**知识库**：领域包（entities / glossary / style / sources）+ 全局 aliases.tsv + git

**每期产物清单**：原始 SRT、修正稿、译文稿、复核稿、终稿、看点内容、审核与审批记录、发布记录、成本记录；评测样本留待后续阶段
